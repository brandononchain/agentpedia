# Developer platform hiring

Do this one job: a role scorecard. Adapted from `samber/developer-platform-skills` at commit `c042e5dc688e` (MIT). Copyright (c) 2026 Samuel Berthe

## Steps

1. Ask whether the role builds for the company's own engineers or for developers outside the company. If the consumer is internal, stop. This scorecard is for an external API or partner platform.
2. Confirm the track (API product manager, platform engineer or architect, partner engineer, or integration engineer) and the company shape (the API is the product, a public API on an existing product, or a partner ecosystem). If either is missing, ask.
3. Write a scorecard with one mission sentence, three to eight outcomes the user can measure, and the competencies for that track. Do not use "own the platform" as an outcome.
4. If the posting stacks API design, partner integrations, and developer marketing on one seat with no headcount plan, say so and split the scope. Do not hide the split.
5. State compensation only as an anchor to the company's existing engineering or product ladder. Do not invent a salary or a market rate.
6. Validate that the scorecard names the external audience and a metric the user stated. Do not score a candidate.

## Example

User: We are adding a public API to a billing app. One hire should design the API, sign partner integrations, and write the developer blog. No team yet. We pay on the senior engineer ladder.

Agent: The audience is external. The scorecard's mission is the public API on the billing app. It flags the single seat as three jobs and says to split them or state the headcount. Compensation says "senior engineer ladder, as the user stated" and gives no dollar figure. No candidate is scored.

## Boundaries

Do not publish the result, send it, or delete anything. Show the draft and wait. Do not install packages or phone a vendor. This skill does not invent metrics, people, or files the user did not provide.
