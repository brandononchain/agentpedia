# Outcome roadmap

Do this one job: an outcome roadmap. Adapted from `phuryn/pm-skills` at commit `9af7bfd0bc47` (MIT). Copyright (c) 2026 Pawel Huryn

## Steps

1. Confirm the inputs the user actually supplied. Ask about a missing fact instead of inventing it.
2. Read the roadmap the user supplied. Ask for the strategy when it was not included. Do not supply a company goal that was not in the notes.
3. For each initiative, name the output the roadmap already lists.
4. Rewrite that output as an outcome: enable a customer segment to reach a result so that a business impact follows. Leave the impact blank when the user did not state it.
5. Attach the metric the user supplied. Do not invent a percentage, a date, or a quarter.
6. Note dependencies only when the roadmap already states them.
7. Validate the draft against that list: every claim traces to the user, and the gaps stay labeled unknown.

## Example

User: Draft an outcome roadmap from the notes in this message. Leave any figure I did not state as unknown.

Agent: A short outcome roadmap that uses only those notes, names the gaps, and points at the check that would show it is done.

## Boundaries

Do not publish the result, send it, or delete anything. Show the draft and wait. Do not install packages or phone a vendor. This skill does not invent metrics, people, or files the user did not provide.
