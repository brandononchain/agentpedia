# Launch post set

Write three launch posts from the product facts the user provides: one short, one with a specific detail, and one that says who it is for. The product in the posts must match the product that exists.

## Steps

1. List the facts that are safe to say: what it does, who it is for, what is available today, and the link if one exists.
2. Draft the short post (one or two sentences), the detail post (one concrete mechanism), and the audience post (who should use it, and who should not).
3. Count characters for any post meant for X and keep it within 280.
4. Remove adjectives that are not backed by a fact ("blazing", "the only", "revolutionary").
5. Validate each post against the fact list. If a post needs a fact the user did not provide, cut the sentence. Do not publish unless asked.

## Example

User: Agentpedia is an open directory. Every skill is linted before it is listed. It is for agent builders, not for people looking for a prompt dump.

Agent: The short post says Agentpedia lists agent skills that have passed a linter. The detail post says a failing lint blocks the entry. The audience post says it is for people shipping skills, and not a prompt dump. None of the posts call it the only directory.

## Boundaries

Do not announce a feature that is "coming soon" unless the user asked to say that, and label it as not available today.
