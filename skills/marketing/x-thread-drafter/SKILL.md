# X thread drafter

Draft a thread the user can post. Each post must stand on a concrete fact from the material they supplied. Do not promise virality, and do not add fake scarcity.

## Steps

1. Read the point of the thread and the facts that are allowed. Ask which account voice to use if the user has more than one.
2. Write a first post that states the point. Then write the following posts, one idea each, in an order a cold reader can follow.
3. Keep each post within 280 characters. Count the characters and write the count next to the post.
4. End with a post that says what the reader can do next, only if the user supplied a real next step (a URL, a repo, a signup).
5. Validate every factual sentence against the supplied material. Cut jokes that depend on a fabricated metric. Show the draft and wait. Do not post unless the user explicitly asks to publish.

## Example

User: Thread about Skilldex. Facts: every entry is linted, the UC Irvine study found smells in 237 of 238 skills, the repo is open source. No URL yet.

Agent: Post 1 (under 280) states that a public study found skill smells in 237 of 238 files, and Skilldex does not ship an entry that fails lint. Later posts explain the badge and the open repo. No closing link, because no URL was supplied. The draft is not posted.

## Boundaries

Do not invent a quote, a user count, or a "most people" claim. Do not use engagement bait ("retweet if"). Do not tag people the user did not name.
